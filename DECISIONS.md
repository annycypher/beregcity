Платформа и стек
D1. Платформа — WordPress, а не самописный PHP.Astra + дочерняя тема astra-child, ACF (free), Elementor Free.Причины: готовая проверенная админка (ИИ-разработка админки с нуля — главныйриск безопасности), скорость запуска, сообщество; каталожные фичи пишутсясвоим кодом ровно под задачу. Самописный план (schema.sql, 12 задач Cline)архивирован в _archive/selfhosted-plan/ — не удалять, справочник логики данных.Следствия: правки только в astra-child и плагине bc-core; ядро и сторонниеплагины не редактируются никогда.

D2. Страницы: Elementor — только статические; статьи — Гутенберг.Контентные статьи организаций (премиум-тариф) собираются из 2–3 Гутенбергblock-patterns; Elementor применяется к статическим страницам («О районе»,«Рекламодателям») и импортируемым .json-шаблонам. Кастомные компоненты(слайдер, категории, сторис, баннеры) — шорткоды [bc_*], встраиваемыев Элементор через виджет «Шорткод».Причина: смешение конструкторов дороже всего на поддержке; граница ясная.

D3. Сторис — собственная реализация.CPT + ACF repeater (фото 1080×1920, link_url, btn_text, caption, is_ad),вьюер на ванильном JS по design/stories.html, без библиотек. Прогресс-бары,автолистание 6 сек, тап-зоны 70/30, свайпы, удержание-пауза, просмотренныесереют (localStorage), предзагрузка кадра. Монетизация: слайд 500–1500 ₽/нед,плашка «Реклама» + erid, максимум 1–2 рекламных слайда на сторис.

D4. Хостинг и среда разработки.Разработка — Local (localwp.com), сайт beregcity.local. Продакшн —SpaceWeb 3–5 ГБ SSD, inode ≥100к, PHP 8.2+, SSL. Перенос — All-in-One WPMigration. 1 ГБ отвергнут: WP + медиатека организаций съест его за год.Покупка хостинга/доменов — в момент готовности Фаз 2–6, не раньше.

D34. Логика фильтров каталога: AND внутри группы, OR между группами.
Выбранные снипеты одной группы объединяются по «И» (например, «Круглосуточно» И «Доставка» внутри группы «Режим работы»); выбранное в разных группах — по «ИЛИ» (группа «Режим работы» ИЛИ группа «Комфорт»). Реализация — WP_Tax_Query: `relation=OR` на уровне групп, `operator=AND` внутри группы. Фильтрованные выборки (≥1 активный фильтр) — `noindex`; программатик-страницы `/katalog/{cat}/{feature}/` — индексируются (canonical на чистый URL).

D35. Антиспам: единый хелпер bc_antispam на всех публичных формах.
Единый механизм защиты (вместо разрозненных проверок в каждом обработчике): honeypot-поле (`name="website"`, скрыт `.hp`), токен формы `md5(form_id + IP + час)` (защита от прямой POST-подачи), отсечка заполнения быстрее 3 сек (timestamp в transient по токену), rate-limit 5 сабмитов / час / IP (скользящее окно). Silent-reject для ботов: ответ 200 и «спасибо», письмо НЕ отправляется, запись в БД НЕ создаётся — фильтры не раскрываем. Фрод-индикаторы в очереди «Утверждение карточек» (D24) — информационные плашки (БЕЗ ФОТО / ТЕКСТ < 200 / ВНЕШНЯЯ ССЫЛКА / FREE-EMAIL / IP-СОВПАДЕНИЕ), карточка с ≥1 красным флагом подсвечивается. Решение всегда за админом; автоблокировки запрещены. Уточнение (4.5-фикс, форма отзыва): rate-limit отзыва — 1/час/IP (bc_antispam_check('review', 1)); остальные формы — 5/час. Причина: отзывы — публичный контент, 5/час с одного IP = рейд/накрутка. Уточнение (4.5-фикс, форма отзыва): rate-limit отзыва — 1/час/IP (bc_antispam_check('review', 1)); остальные формы — 5/час. Публичный ящик — hello@beregcity.ru, admin@beregcity.ru — технический (не публикуется). Оферта тарифов и Правила размещения — отдельным шагом перед продажами. D38. Клейминг витринных карточек (3б, утверждено 08.10.2026).
Витринная карточка (импорт D10, тариф free) может быть «клеймлена»: организация заявляет права, проходит проверку и получает ЛК. Механика — таблица wp_bc_claims (id, post_id, user_id, name, email, phone, role, comment, status, token, ip, created_at); статусы new → verified → approved|rejected. Верификационный ключ — постоянная колонка token (varchar 64, 32 случайных байта в hex), сверка hash_equals, одноразовый (обнуляется после верификации); заявки, висящие в new более 14 дней, считаются просроченными. Форма на карточке — шорткод [bc_claim] (скрыт, если карточка уже клейменная или текущий пользователь — владелец); защита — bc_antispam_* + bc_consent_*; письма — bc_mail (админу — новая заявка, заявителю — подтверждение/верификация/результат).
Верификация прав — ЗВОНКОМ НА ТЕЛЕФОН ИЗ КАРТОЧКИ (публичный номер организации), НЕ на телефон из заявки: цель — подтвердить, что заявитель представляет организацию. Нет дозвона — отклонить с причиной «не удалось подтвердить по телефону».
Привязка (админ-экран «Заявки на права», 5-я очередь дашборда): поиск/создание пользователя org_manager по e-mail (логин = e-mail, роль org_manager; пароль не показывается — письмо-сброс через retrieve_password); post_author = пользователь, post_status = published; если тариф пуст — записать free (сортировка и лимиты сразу корректны); claim → approved + user_id; письмо «Доступ открыт» + /kabinet/. Отклонение — причина обязательна, IP заявки → wp_options.bc_rejected_ips (фрод-индикатор D35). Действия — GET + nonce (паттерн approval, D24).
Состояние «клейменная free»: описание карточки выводится только у клейменной (bc_is_claimed() — автор с ролью org_manager) и в пределах лимита free (≤300 знаков); витринная карточка без владельца — без описания. Модерация витрины (D24) трактуется как презентация организации: карточка может быть опубликована до появления владельца, права переходят по клеймингу.

D39. Тарифная визуализация фото (3б, утверждено 08.10.2026).
Обработка и перезапись файлов ЗАПРЕЩЕНЫ — только динамический CSS-фильтр на выводе (обратимо при смене тарифа, медиафайлы не трогаются). Фильтр «тёплый сепия-беж» (не мёртвый серый): filter: grayscale(1) sepia(.45) saturate(.7) brightness(1.04). Применяется ТОЛЬКО к free: .org-card.is-free .org-cover img, .org-card.is-free .gal-main img, .sim .org-card.is-free .org-cover img, .org-head.is-free .gal-main img. Классы is-free/is-standard/is-premium (а также is-trial) проставляются по BC_Plans на .org-card (сетка каталога и «Похожие рядом») и на .org-head карточки организации. На free рендерится одно фото (обложка), миниатюры не выводятся; без фото — SVG-плейсхолдер (как в референсе). Платные тарифы, аватар в шапке ЛК и превью не фильтруются. Админ-предпросмотр D24 («предпросмотр как на сайте») показывает тот же фильтр — это фронтенд-страница карточки. В ЛК на free — строка-стимул (У1): «Ваши фото показываются в тёплом ч/б — цветные открываются на тарифе Стандарт» (+ ссылка на вкладку тарифа); в таблице тарифов ЛК — строка «Цветные фото: ✕/✓/✓». Файлы: theme.css (фильтр), template-parts/org-card.php и single-organizations.php (классы, free — 1 фото), page-kabinet.php (стимул + строка тарифов). СПРАВОЧНИК §2: «Фото: free 1 (сепия) / Стандарт 8 / Премиум 25».

D40. Отзывы организаций (Этап 4.5, утверждено 08.10.2026).
Отзыв — комментарий к организации (таблица wp_comments), отдельной CPT/таблицы нет. Оценка 1–5 — в comment meta bc_rating. Модерация: новый отзыв создаётся в статусе hold и публикуется после одобрения. Данные: комментарии у CPT organizations включаются через add_post_type_support( organizations, comments ) (файл reviews.php). Форма на карточке — шорткод [bc_reviews]: имя + оценка + текст + обязательное согласие ПДн (bc_consent_*); защита — bc_antispam_check( review ) (honeypot/токен/время/rate-limit); после отправки — письмо редакции (bc_mail) и запись в лог согласий (context review). Вывод: сводка (средний рейтинг + количество + «модерация перед публикацией») и список одобренных отзывов со звёздами. Ответ организации — comment meta bc_org_reply, доступен только владельцу (author = текущий пользователь) на тарифе Стандарт+; выводится блоком «Ответ организации». Модерация — «БерегСити → Отзывы» (очередь hold: одобрить / отклонить в корзину) + плитка «Отзывы на модерации» на дашборде. Сортировка каталога по рейтингу (filters.php) — отдельным шагом. Файлы: includes/reviews.php (new), admin/class-bc-admin.php, single-organizations.php.
