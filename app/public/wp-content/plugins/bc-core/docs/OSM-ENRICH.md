# Дозаполнение карточек из OSM и VK

Как наполнить 40 черновиков «Организаций» телефонами, графиком, сайтами и соцсетями из открытых источников. Данные OSM — под лицензией ODbL (указывать источник: © OpenStreetMap).

## 1. Выгрузка OSM

```
wp bc-osm scan                       # микрорайон по координатам карточек (±0.012°), тайлы 0.012°
wp bc-osm scan --mode=city           # весь населённый пункт (bbox из Nominatim), дольше и шумнее
wp bc-osm scan --bbox=55.98,92.87,56.02,92.93
wp bc-osm scan --tile=0.006          # мельче тайлы (если таймаут)
wp bc-osm scan --source=osmapi       # только api.openstreetmap.org (когда Overpass перегружен)
wp bc-osm scan --import=/tmp/osm-merged.json   # импорт готовой выгрузки (Overpass-формат)
```

- Источник по умолчанию: Overpass API (`overpass-api.de` + зеркала), при 502/504 — резерв `api.openstreetmap.org/api/0.6/map`.
- Кэш ответов: `wp-content/uploads/bc-osm/cache/`, повторный запуск почти без сети (`--force` — игнорировать).
- Результат: `uploads/bc-osm/osm-scan-<дата>.json` и `.csv` (разделитель `;`, BOM для Excel).
- Что забираем: `name`, `addr:*`, `phone`/`contact:phone`, `opening_hours`, `website`/`contact:website`, `contact:vk|telegram|whatsapp|instagram`, координаты (центр для way).
- Опция `bc_osm_city` (по умолчанию «Красноярск») — город для Nominatim и VK.

## 2. Дозаполнение карточек

```
wp bc-osm enrich --dry-run           # таблица «карточка → объект OSM → балл → какие поля добавятся»
wp bc-osm enrich                     # реальная запись
wp bc-osm enrich --threshold=0.75    # строже (по умолчанию 0.6)
wp bc-osm enrich --file=/path/osm-scan-2026-10-19.json
```

Правила:

- Сравнение — по нормализованному названию: нижний регистр, без `ООО/ИП/ЗАО`, кавычек и пунктуации; типовые слова («аптека», «салон», «центр»…) отбрасываются.
- Порог считается **по названию**, а не по сумме: совпадение с улицей и близость точки только повышают приоритет среди кандидатов.
- Дополнительно требуется «строгий» критерий: точное имя (или имя без типового слова) либо посимвольная близость ≥ 0.7. Это отсекает совпадения вида «Домми» ↔ «Авто-Дом».
- Заполняются **только пустые** поля: `bc_lat`/`bc_lng`, `bc_phone` + `bc_phones` (JSON), `bc_schedule_text` (opening_hours → «Пн–Пт 09:00–20:00»), `bc_website`, `bc_socials` (JSON) + `bc_vk`/`bc_telegram`/`bc_whatsapp`, `bc_osm_id`.
- Непустые поля не меняются: расхождения печатаются в отчёт («в карточке … , в OSM …»).
- Карточки, оставшиеся без координат, добираются через Nominatim (пауза 1.1 с, кэш `bc_geocode_cache`).
- График, который не удалось разобрать (`sunrise-sunset`, `Apr-Oct`), не записывается — чтобы в карточке не появился мусор.

## 3. ВКонтакте (опционально)

```
define( 'BC_VK_TOKEN', 'сервисный ключ' );   // wp-config.php

wp bc-vk test                        # проверка токена
wp bc-vk enrich --dry-run            # только карточки без телефона
wp bc-vk enrich
```

`groups.search` (название + город) → `groups.getById(fields=contacts,place)` → телефоны в `bc_phone`/`bc_phones`, ссылка сообщества в `bc_socials.vk` и `bc_vk`. Порог по названию тот же, пауза 0.7 с, кэш в опции `bc_vk_cache`. Без токена команда предупреждает и завершается, ничего не меняя.

## 4. Что видит посетитель

Карточка организации (`/katalog/organization/<slug>/`):

- все телефоны — ссылками `tel:` (первый — терракотовой кнопкой, остальные — «стеклянные»);
- сайт — внешняя ссылка `target="_blank" rel="nofollow noopener"`;
- соцсети ВК/Telegram/WhatsApp — кнопки с `nofollow noopener`;
- «Маршрут» — Яндекс.Карты по координатам (`rtext=~lat,lng`);
- график из `bc_schedule_text` — строкой «График: …» с серой точкой (без ложного «Сегодня закрыто»);
- карта — по `bc_lat`/`bc_lng`, при их отсутствии остаётся заглушка.

Мобильная панель звонка по-прежнему ведёт на `/go/{id}/phone/` — счётчик кликов сохраняется.

## 5. Проверка
