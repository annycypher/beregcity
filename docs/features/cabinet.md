Роль и доступ
Роль WP: org_manager. Запрещён wp-admin, админ-бар скрыт.
Регистрация: email + пароль + название организации + категория + телефон. Карточка создаётся со статусом ожидания. Письмо админу: новая заявка.
Админ одобряет → опубликован → запускается триал 7 дней (trial_until = дата одобрения +7).
У одной учётки — одна организация (post_author).

Таблица wp_yub_payments: id, org_id, plan, period, amount, method(manual|yukassa),yk_payment_id, status(created|paid|активированный|отклонённый), created_at, activated_at, plan_until.
Активация ТОЛЬКО через Yub_Plans::activate(org, plan, period, payment_id)→ plan_until = max(today, текущий plan_until) + период. Один код для ручного и авто.
v1: страница «Тариф и оплата» показывает тарифы (месяц/3 мес −5%/год −10%),реквизиты, сумму; после перевода организация жмёт «Я оплатил(а)» → статус создан; админ в админке видит очередь и кнопкой «Подтвердить» вызывает activate().
v2 Юkassa: кнопка «Оплатить» → создание платежа по API → редирект →webhook → проверка → activate(). Рекуррентность для автопродления.Требования: ИП, договор, политика оплаты. Секретные ключи — в wp-config константы.
Все платежи — операции с erid-не относится; чеки v2 через Юкасса (54-ФЗ).
Статистика ЛК
Счётчики: просмотры карточки (дедуп по cookie/сутки), клики телефон/сайт/мессенджеры/кнопка заявки (через /go/{id}-подобные эндпоинты с nonce-подобной защитой от ботов).
Витрина в кабинете: за 7/30 дней + сравнение с прошлой неделей.
Главный продающий текст продлений: «Вашу карточку видели N раз, M кликов по телефону».
Модерация
Карточка: ожидает → опубликована (админ). Правка карточки после published:текстовые поля меняются сразу, фото и снипеты — мгновенно (доверие послепервой модерации, как в механике новостей).
Кастомные ярлыки и ключевые слова — всегда через одобрение.
Отклонение — с причиной из шаблона (нет фото/не хватает данных/не относится к району).

13. Счета на оплату — v1, «все форматы» (D25)
При выборе тарифа в ЛК счёт создаётся АВТОМАТИЧЕСКИ: запись в wp_bc_payments со статусом created + страница счёта.
Форматы v1 (без composer-библиотек):
· экран счёта в браузере — HTML-шаблон bc-core (лого, реквизиты из СПРАВОЧНИКА, позиция «Тариф …, период», сумма, «НДС не облагается»), кнопка «Печать / Сохранить PDF» (@media print — печатается только счёт);
· письмо организации — тот же счёт в теле письма (wp_mail, HTML) + ссылка;
· ссылка на счёт с публичным токеном (для пересылки в мессенджер).
Два вида документа: «Счёт на оплату» (для ИП/ООО, с реквизитами сторон) и «Квитанция» (для физлица: перевод по карте/СБП) — вид выбирается в ЛК.
PNG/DOC-выгрузка и закрывающие документы (акт, УПД) — v2, при Юkassa (D8).
Счёт живёт в ЛК во вкладке «Тариф и оплата»: история платежей + кнопки «Смотреть счёт» / «Отправить на почту».

14. Роли и права (D26)
· administrator — всё; editor — контент редакции + модерация (без платежей);
· org_manager — своя организация через ЛК (уже в v1.0);
· v2: org_staff — сотрудник, приглашённый владельцем организации по email из ЛК («Команда»: добавить/удалить), права = только его организация.
Выдача прав: стандартный экран WP «Пользователи» (админ); роли создаёт bc-core при активации. Отдельный экран прав НЕ строим.

15. Карта в админке (D27)
Координаты организации: поля lat/lng (ACF) + подсказка «ПКМ на Яндекс Картах → что здесь? → скопируйте координаты».
Клик-карта (мини-карта Яндекса в админке, тап ставит метку) — ТОЛЬКО после переноса, под флагом BC_MAP_ON (D11). На Local — ручной ввод.
На фронте карточки метка рендерится из координат (карта-заглушка до флага).
